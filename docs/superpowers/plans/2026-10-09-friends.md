# Friends Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A Friends page in the sidebar where a person finds others by name or friend code, sends and answers friend requests, and keeps a friends list.

**Architecture:** A small public directory (`profiles/{uid}`, `friendCodes/{code}`) that each person's client keeps in sync from their own account document, plus `friendships/{a_b}` documents shared by the two people. Search is a name-prefix query on `profiles` or one `get` on `friendCodes`; nothing else of an account is ever readable.

**Tech Stack:** React 19, Firebase Firestore, node `*.check.mjs` checks, rules tests (`npm run test:rules`, emulator).

**Spec:** `docs/superpowers/specs/2026-10-09-friends-and-inbox-design.md` (Friends part). Inbox is a separate plan.

## Global Constraints

- Real accounts only (`isRealUser()` in rules, `isAccountUser` on the client); never quick-session or old club logins.
- Tokens for colors, new CSS in `src/clubs.css` only; sentence case; no avatar-initial badges next to names (owner's rule).
- Names 1 to 60 characters; no extra fields (`hasOnly`).
- Friend code: 8 characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (the invite-code alphabet).
- Emails are never in the directory. Searching shows names only.
- The working tree has someone else's uncommitted theme edits (`Profile.jsx`, `Settings.jsx`, `theme.js`, ...). Commit only your own changes: for a file that holds their hunks, stage a blob made from `HEAD` plus your edit (see memory `active-queue-and-sidebar`), and build the index tree before each commit (`git checkout-index -a --prefix=$TEMP/headtree/`, link `node_modules`, `npx vite build`).

## Review Focus

1. Someone with "find me by name" off must not be listable by name, and turning it off must remove the `profiles` doc; the friend code must still work.
2. Nobody can overwrite or delete another person's `friendCodes` or `profiles` doc, or claim a friendship they are not in.
3. A pending request can be accepted only by the other person, never by its sender; a sender can't change the names of the other person.
4. Sending a request when one already exists (either direction), to yourself, or to a person who removed you.
5. Renaming yourself: the directory, the friend code doc and your friendships' stored names all follow, and nothing loops.

### Task 1: Pure helpers (`utils/friends.js`)

**Files:**
- Create: `src/utils/friends.js`, `src/utils/friends.check.mjs`

**Interfaces (produces):**
- `newFriendCode()` (same alphabet and length as `newInviteCode`), `normalizeCode(text)` → upper-case, spaces and dashes removed; `isFriendCode(text)` → boolean (8 chars from the alphabet).
- `nameKey(name)` → trimmed, lower-case (what `profiles.nameLower` holds); `nameRange(text)` → `[start, end]` for the prefix query (`end = start + ""`), or `null` for text shorter than 2 characters.
- `pairId(a, b)` → the two uids sorted and joined with `_`; `friendshipDoc(me, meName, other, otherName, now)` → `{ users: [lo, hi], names: { [me]: meName, [other]: otherName }, status: "pending", requestedBy: me, createdAt: now }`.
- `relationTo(friendships, me, other)` → `"friends" | "sent" | "received" | "none"`.
- `needsDirectorySync(account)` → true when `friendCode` is missing, or `directory` (`{ name, discoverable, code }`) differs from the account's current name / `discoverable !== false` / `friendCode`.
- `directoryDocs(uid, account)` → `{ code, codeDoc: { uid, name }, profile: { name, nameLower } | null }` for the current state (`profile` is `null` when `discoverable === false`).

import {

assert.equal(newFriendCode().length, 8);

assert.equal(isFriendCode(""), false);

assert.equal(nameKey("  Louie A "), "louie a");
assert.deepEqual(nameRange("Lou"), ["lou", "lou"]);
assert.equal(nameRange("L"), null);   // one letter would list half the directory
assert.equal(nameRange("  "), null);

assert.equal(pairId("b", "a"), "a_b");

  { id: "a_d", users: ["a", "d"], status: "pending", requestedBy: "d" },

assert.equal(relationTo(list, "b", "a"), "friends");

assert.equal(relationTo(list, "a", "d"), "received");

assert.equal(needsDirectorySync({ ...acct, discoverable: false }), true);          // switch turned off
assert.equal(needsDirectorySync({ name: "Lou" }), true);                           // no code yet
assert.equal(needsDirectorySync({ ...acct, directory: undefined }), true);

assert.equal(directoryDocs("u1", { ...acct, discoverable: false }).profile, null);
assert.equal(directoryDocs("u1", { ...acct, name: "x".repeat(80) }).codeDoc.name.length, 60);

- [ ] **Step 3: Implement** in `firestore.rules` (inside the existing `match /databases/{database}/documents`):

```
    // ---- Friends. A small public directory (names only, never email) and the friendships between two people.
    function validFriendCode(c) { return c.matches('^[ABCDEFGHJKLMNPQRSTUVWXYZ23456789]{8}$'); }
    match /profiles/{uid} {
      allow get: if isRealUser();
      allow list: if isRealUser() && request.query.limit <= 20;
      allow create, update: if isRealUser() && request.auth.uid == uid
        && request.resource.data.keys().hasOnly(['name', 'nameLower'])
        && validName(request.resource.data.name)
        && request.resource.data.nameLower == request.resource.data.name.trim().lower();
      allow delete: if isRealUser() && request.auth.uid == uid;
    }
    match /friendCodes/{code} {
      allow get: if isRealUser();
      allow create: if isRealUser() && validFriendCode(code)
        && request.resource.data.keys().hasOnly(['uid', 'name'])
        && request.resource.data.uid == request.auth.uid && validName(request.resource.data.name);
      allow update: if isRealUser() && resource.data.uid == request.auth.uid
        && request.resource.data.keys().hasOnly(['uid', 'name'])
        && request.resource.data.uid == request.auth.uid && validName(request.resource.data.name);
      allow delete: if isRealUser() && resource.data.uid == request.auth.uid;
    }
    match /friendships/{pair} {
      allow get, list: if isRealUser() && request.auth.uid in resource.data.users;
      allow create: if isRealUser()
        && request.resource.data.keys().hasOnly(['users', 'names', 'status', 'requestedBy', 'createdAt'])
        && request.resource.data.users.size() == 2
        && request.resource.data.users[0] < request.resource.data.users[1]
        && pair == request.resource.data.users[0] + '_' + request.resource.data.users[1]
        && request.auth.uid in request.resource.data.users
        && request.resource.data.requestedBy == request.auth.uid
        && request.resource.data.status == 'pending'
        && request.resource.data.names.keys().hasOnly(request.resource.data.users)
        && request.resource.data.names.keys().hasAll(request.resource.data.users)
        && validName(request.resource.data.names[request.resource.data.users[0]])
        && validName(request.resource.data.names[request.resource.data.users[1]])
        && nearNow(request.resource.data.createdAt);
      // The other person accepts (status only); either person may refresh their own name in `names`.
      allow update: if isRealUser() && request.auth.uid in resource.data.users
        && ((resource.data.status == 'pending' && request.auth.uid != resource.data.requestedBy
              && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status'])
              && request.resource.data.status == 'accepted')
          || (request.resource.data.diff(resource.data).affectedKeys().hasOnly(['names'])
              && request.resource.data.names.diff(resource.data.names).affectedKeys().hasOnly([request.auth.uid])
              && validName(request.resource.data.names[request.auth.uid])));
      allow delete: if isRealUser() && request.auth.uid in resource.data.users;
    }
```

# Club feed (step 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The club's Announcements tab becomes a **Feed**:
- every member posts (text plus one optional photo);
- managers can mark a post as an announcement, which stays pinned for 7 days;
- people heart posts and reply one level deep;
- the author or a manager deletes a post or reply.

**Architecture:** Posts stay in `clubs/{id}/announcements`. Each post doc carries `hearts` (uids), `replyCount`
and `lastReplyId`. Each post's photo and replies live in their own subcollections, so the list stays light. The rules
check every part of each write:
- a heart write changes only your own uid;
- the reply count moves only in the same batch as a reply create or delete (`getAfter` / `existsAfter`);
- a post and its photo are created in one batch.

Pure logic (order, pin, hearts, "New", role tag) is in `utils/feed.js`; reads and writes are in `hooks/useFeed.js`;
the screen is `views/ClubFeed.jsx`.

**Tech Stack:** React 18 + Vite, Firebase JS SDK (Firestore), `firestore.rules`, `@firebase/rules-unit-testing`,
`node` assert checks, lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-12-club-header-and-feed-design.md`, goal 4 and Data (Posts, Post photo,
Replies, Delete cascade, Account delete, Who deletes a reply). Mockup: `.superpowers/brainstorm/510-*/content/club-header-feed.html`
(feed and phone sections). Step 3 (Overview, Members) gets its own plan.

## Global Constraints

- **Text:** a post is 1-2000 characters, a reply 1-1000. Both are trimmed, and spaces only is refused, in the app and
  in the rules (`text.trim().size() >= 1`).
- **Photos:** at most one photo per post, a JPEG data URL up to 1280 px, ≤ 380,000 characters (`isJpeg`), at
  `announcements/{id}/photo/main` = `{ image }`. Replies have no photos.
- **Who:** only members read. Every member posts. Only owners and managers set `announcement: true`. A post with no
  `announcement` field (written before this change) counts as an announcement.
- **Pin:** an announcement is pinned above the rest while it is less than 7 days old (`PIN_MS = 7 * 86400000`). After
  that it sits in time order with the rest.
- **"New":** a post less than 24 hours old (`NEW_MS = 86400000`; used by the Overview in step 3, but defined and checked
  here).
- **Paging:** the newest 20 posts, then "Load earlier posts" (+20).
- **Post header:** author name, role tag (Owner / Manager / Member, from `authorRole`), time. Names are plain text: no
  avatars or initials.
- **Styling:** theme tokens only, light and dark. New styles go in a section "Club feed (2026-11-12)" at the end of
  `src/clubs.css`. Tap targets are about 40 px on touch screens (`max-width:700px, pointer:coarse`). The side column is
  hidden on a phone.
- **Firebase:** no Storage. The rules must be re-published in the Firebase console.
- **Browser checks:** run them on the emulators in the visible Playwright window (`npm run emulators`,
  `npm run dev:emu`, `node scripts/seed-help.mjs`). Logins `ann@demo.test` (owner of `pub`) and `eli@demo.test`
  (member), password `password1`. Check at 390 px and 1280 px, light and dark.
- **Rules tests:** run directly (`node tests/feed.test.mjs`) while the dev emulators hold port 8080.
- **Commits:** only when the owner asks. Each task ends with "stage".

## Review Focus

1. **A member forging counts or hearts:**
   - adding someone else's uid to `hearts`;
   - adding their own uid twice;
   - setting `replyCount` with no reply;
   - creating a reply without bumping the count.

   Expected: refused. → Task 2 tests.
2. **Old posts** (no `announcement`, `hearts`, `replyCount`, `authorRole`): they show as manager announcements, can be
   hearted (`get('hearts', [])`) and replied to (`get('replyCount', 0)`). → Task 1 check (`isAnnouncement`), Task 2
   tests seed one old post.
3. **Deleting a post with replies and a photo:** nothing is left behind, including when a manager deletes a member's
   post, or when the whole club is deleted. → Task 2 tests (batch delete), `tests/cascade.test.mjs`.
4. **A person who left the club:** they can no longer read, post, heart or delete. → Task 2 tests (a stranger who is
   the author of a seeded post is refused the delete).
5. **A pinned announcement older than the first page:** it still pins (it comes from its own 7-day query, not the
   page), and it shows once, not twice. → Task 1 check (`feedOrder` de-duplicates by id).

**Interfaces:**
- Produces:

    `Error("Posts can be up to 2000 characters.")` (or `"Replies can be up to 1000 characters."` when `max` is

**Interfaces:**
- Produces, in `src/utils/feedData.js` (shared by the hooks and the cascade, like `friendsData.js`):
  - `postRef(db, clubId, id)`
  - `deletePostBatch(db, clubId, postId) -> Promise`: it reads the post's `replies` and then commits one batch that
    deletes every reply, `photo/main` and the post. A `ponytail:` comment notes the ceiling: one batch holds about
    490 replies.
- The rules' shape inside `match /announcements/{postId}` (helper names are free; the conditions are exact):

  **Read:** `isMember(clubId)`.

  **Create:**
  - keys are exactly `authorId`, `authorName`, `authorRole`, `text`, `createdAt`, `announcement`, `hasPhoto`,
    `hearts`, `replyCount`;
  - `authorId == auth.uid`;
  - `authorName == member.name` and `authorRole == member.role`;
  - `text` is a string, `trim().size() >= 1`, and `size() <= 2000`;
  - `nearNow(createdAt)`;
  - `announcement is bool`, and `!announcement || isManager`;
  - `hasPhoto is bool`, and `hasPhoto == existsAfter(.../photo/main)`;
  - `hearts == []` and `replyCount == 0`.

  **Update, heart** (`affectedKeys().hasOnly(['hearts'])`), with old = `resource.data.get('hearts', [])` and new =
  `request.resource.data.hearts`:
  - `new.toSet().difference(old.toSet()).hasOnly([uid])`;
  - `old.toSet().difference(new.toSet()).hasOnly([uid])`;
  - `new.size() == new.toSet().size()`, so no duplicates;
  - `new.size() - old.size()` is 1 or -1.

  **Update, reply count** (`affectedKeys().hasOnly(['replyCount', 'lastReplyId'])`), with r =
  `replies/$(request.resource.data.lastReplyId)`:
  - either `replyCount == resource.data.get('replyCount', 0) + 1 && !exists(r) && existsAfter(r)`;
  - or `replyCount == old - 1 && exists(r) && !existsAfter(r)`.

  **Delete:** `isMember && (resource.data.authorId == auth.uid || isManager)`.

  **`match /photo/{name}`:**
  - read if `isMember`;
  - create if `name == 'main'`, keys only `image`, `isJpeg(image, 380000)`, and
    `getAfter(post).data.authorId == auth.uid && getAfter(post).data.hasPhoto == true && !exists(post)`, so only in
    the post's create batch;
  - delete if `isMember && !existsAfter(post) && (get(post).data.authorId == auth.uid || isManager)`;
  - no update.

  **`match /replies/{replyId}`:**
  - read if `isMember`;
  - create if:
    - keys are exactly `authorId`, `authorName`, `text`, `createdAt`;
    - author is self, `authorName == member.name`;
    - text is trimmed and 1-1000 characters;
    - `nearNow`;
    - `getAfter(post).data.replyCount == get(post).data.get('replyCount', 0) + 1`;
    - `getAfter(post).data.lastReplyId == replyId`.
  - delete if `isMember`, and:
    - the caller is the reply's author, a manager, or the post's author (`get(post).data.authorId`);
    - and either the post is gone after the batch (`!existsAfter(post)`), or `getAfter(post).data.replyCount ==
      get(post).data.get('replyCount', 0) - 1 && getAfter(post).data.lastReplyId == replyId`.
  - no update.

  `isMember` and `isManager` read the member record on every request, so leaving the club ends all access.

**Interfaces:**
- Consumes: `feed.js` (Task 1), `feedData.js` (Task 2), `compressImage(file, { steps, max, message, tooLarge })` from
  `utils/receipt.js`.
- Produces:
  - `useFeed(clubId) -> { posts, pinned, ready, error, hasMore, loadMore }`.
    - `posts` comes from `orderBy("createdAt","desc"), limit(n)`, where `n` starts at `PAGE` and `loadMore` adds
      `PAGE`.
    - `pinned` comes from a second listener, `where("createdAt", ">", now - PIN_MS)` (no composite index: same
      field), filtered with `isPinned`. `now` is taken when the hook mounts.
    - `hasMore` is `posts.length === n`.
  - `useReplies(clubId, postId | null) -> { replies, ready }`: ordered by `createdAt` asc, listening only while open.
  - `usePostPhoto(clubId, postId | null) -> string`: one `getDoc` per post, cached in a module `Map` (posts never
    change their photo).
  - `useFeedActions({ clubId, uid, role })`:
    - `publish({ text, announcement, file })`: `cleanText`, then the member name (read like today), then one batch:
      the post plus `photo/main` when `file` is set;
    - `toggleHeart(post)`: `arrayUnion` / `arrayRemove` of `uid`;
    - `reply(post, text)`: one batch of `replies/{newId}` plus the post's `replyCount: increment(1), lastReplyId`;
    - `removeReply(post, reply)`: a batch with `increment(-1)`;
    - `removePost(post)`: `deletePostBatch`.
    - Errors from `cleanText` and `compressImage` pass through; ClubApp shows them.
